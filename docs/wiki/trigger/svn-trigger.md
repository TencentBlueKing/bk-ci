# SVN 事件触发

当 SVN 代码库有**新的提交**时，自动启动流水线。

- 入口：**流水线编辑 → 触发器 → 新增「SVN 事件触发」**
- 可视化配置与 PAC YAML `on`（`type: svn`）双向同步
- 需要先在**代码库**中关联对应的 SVN 仓库，蓝盾会自动注册提交钩子

## 能力概览

SVN 触发只监听**提交事件**（Post Commit），通过路径和人员过滤控制哪些提交会启动构建。

| 典型场景 | 配置方式 |
|----------|----------|
| 仓库内任意提交都构建 | 不填路径 |
| 只关心某个子目录 | 相对路径填子目录，如 `trunk/src` |
| 忽略文档、资源等目录 | 排除路径填对应目录 |
| 忽略机器人账号的提交 | 排除人员填机器人账号 |

## 配置触发器

### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| 代码库 | 「按代码库选择」或「按代码库别名输入」（别名可写成流水线变量） | — |
| 相对路径 | 相对于**代码库地址**的路径，多个用英文逗号分隔。提交中有任一文件命中即触发。留空 = 代码库地址下的全部路径 | `trunk/src,trunk/lib` |
| 排除以下路径 | 相对于代码库地址的路径，多个用英文逗号分隔。参与判断的文件全部命中时不触发 | `trunk/docs` |
| 包含以下人员 | 只有这些人的提交才触发 | — |
| 排除以下人员 | 这些人的提交不触发，**排除优先于包含** | `robot` |

- 路径、人员都支持 `${{ variables.xxx }}` 引用流水线变量。
- 人员按 SVN 提交用户名**精确匹配**。

### 路径的计算方式

配置的路径会拼在**代码库地址的子路径**后面再和提交的文件比对。例如代码库地址是 `http://svn.example.com/group/project/trunk`：

| 配置的相对路径 | 实际比对的路径 |
|----------------|----------------|
| 留空 | `trunk`（即整个代码库地址） |
| `src` | `trunk/src` |
| `src,docs` | `trunk/src` 或 `trunk/docs` |

提交的文件如果不在代码库地址下（例如提交到了同仓库的 `branches/` 目录），不会触发。

### 路径匹配方式

| 路径匹配方式 | PAC 值 | 规则 | 示例 |
|--------------|--------|------|------|
| 前缀匹配（默认） | `NamePrefixFilter` | 提交文件路径以配置路径开头即命中 | `src` 命中 `trunk/src/a.cpp` |
| 通配符匹配 | `RegexBasedFilter` | Ant 风格通配符：`*` 不跨 `/`，`**` 可跨多层，`?` 单个字符 | `src/**/*.cpp` |

可视化默认使用前缀匹配；需要通配符匹配时在 PAC 中配置 `path-filter-type`。

## 输出变量

触发成功后，可在流水线中引用本次提交信息。

### 公共

| 变量 | 说明 |
|------|------|
| `${{ ci.event }}` | 事件类型，固定为 `POST_COMMIT` |
| `${{ ci.actor }}` | 提交人 |
| `${{ ci.sha }}` | 本次提交的版本号（revision） |
| `${{ ci.repo }}` | SVN 项目名 |
| `${{ ci.repo_alias_name }}` | 蓝盾代码库别名 |
| `${{ ci.repo_type }}` | 代码库类型 |
| `${{ ci.build_msg }}` | 构建信息，默认取提交说明 |

### SVN 专有

| 变量 | 说明 |
|------|------|
| `${{ BK_CI_REPO_SVN_WEBHOOK_REVERSION }}` | 提交版本号 |
| `${{ BK_CI_REPO_SVN_WEBHOOK_USERNAME }}` | 提交人 |
| `${{ BK_CI_REPO_SVN_WEBHOOK_COMMIT_TIME }}` | 提交时间（时间戳） |

## PAC YAML 配置

PAC v3.0 中，每个代码库对应 `on` 列表里的一项，用 `type: svn` 标识，`repo-name` 填代码库别名，提交事件写在 `push` 下。

> **`type: svn` 必须写**。省略 `type` 时一律按 `git` 解析，配置不会生效。

| 字段 | 对应可视化字段 |
|------|----------------|
| `paths` | 相对路径 |
| `paths-ignore` | 排除以下路径 |
| `users` | 包含以下人员 |
| `users-ignore` | 排除以下人员 |
| `path-filter-type` | 路径匹配方式，省略 = `NamePrefixFilter` |

> SVN 没有分支概念，`branches`、`action` 等 Git 字段写了也不生效。

### 基本用法

```yaml
on:
  - type: svn
    repo-name: group/project
    push:
      paths:
        - src
        - lib
      paths-ignore:
        - docs
      users-ignore:
        - robot
```

### 通配符匹配

```yaml
on:
  - type: svn
    repo-name: group/project
    push:
      path-filter-type: RegexBasedFilter
      paths:
        - "src/**/*.cpp"
        - "src/**/*.h"
```

### 与其他触发并列

```yaml
on:
  - manual: enabled
    schedules:
      - cron: "0 2 * * *"
  - type: svn
    repo-name: group/project
    push:
      paths:
        - src
```

## 常见问题

**Q：配了触发器却没有启动？**
进入**流水线详情 → 触发事件**标签页，查看对应事件的未匹配原因。常见原因：提交的文件不在代码库地址下；路径没有命中或被排除；提交人被排除或不在包含名单中。

**Q：相对路径要不要带代码库地址里的目录？**
不要。相对路径是相对于代码库地址的，代码库地址是 `.../project/trunk` 时写 `src` 即可，不要写成 `trunk/src`。

**Q：同一个 SVN 仓库的不同目录要分别触发不同流水线？**
在蓝盾里把各目录分别关联成代码库（代码库地址指向具体目录），各流水线选择对应的代码库；或者共用一个代码库，在各流水线的触发器里配置不同的相对路径。

**Q：一次提交改动的文件很多，路径过滤还准吗？**
单次提交的变更文件达到 999 个时，文件明细不完整，系统改用这次提交涉及的路径列表做匹配，粒度会变粗。对路径过滤很敏感的场景，建议拆分大提交。
